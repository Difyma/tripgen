## 1. Воркфлоу SERP поиска

### Вопрос Островок:
> Вижу, что вы интегрировали все виды SERP поиска, которые по сути являются альтернативой друг другу. Подскажите, пожалуйста, как ваша система понимает, какой вид поиска реализовать в моменте? Как это выглядит для пользователя в чате? Возможно ли с вашей стороны сфокусироваться на одном виде SERP?

### Ответ:

**Текущая логика выбора endpoint:**

```typescript
// Приоритет использования endpoint-ов:
1. /search/serp/region/ - основной метод (по умолчанию)
2. /search/serp/geo/ - fallback при пустых результатах из региона
```

**Алгоритм:**
1. Сначала пробуем `/search/serp/region/` с нормализованным названием региона
2. Если результатов нет ИЛИ у региона есть координаты (lat/lng) → пробуем `/search/serp/geo/`
3. Если geo тоже не дал результатов → используем fallback

**Для пользователя это выглядит так:**
- Пользователь пишет в чат: "Найди отели в Москве"
- AI определяет намерение и извлекает параметры (даты, гости, бюджет)
- Система автоматически выбирает наиболее подходящий endpoint
- Результаты отображаются единообразно — пользователь не видит разницы

**Готовы скорректировать:**
Да, можем сфокусироваться только на `/search/serp/region/` как основном методе. Уберем `/search/serp/geo/` из fallback-цепочки, оставив только его для случаев когда явно указаны координаты (что редко).

## 2. Логика между SERP и чатботом (тестовые отели)

### Вопрос Островок:
> Подскажите, пожалуйста, какая логика между использованием SERP поиска и работой чатбота? Когда я вводила различные запросы, чат либо не находил ничего, либо всегда предлагал одинаковый отель – тестовый – и в логах при этом ни один из API методов не триггерился. Что происходит (или что ожидается) под капотом, когда пользователь ищет в чате?

### Ответ:

**Объяснение ситуации с тестовыми отелями:**

В текущей конфигурации **включен режим fallback** на тестовые отели для development-окружения:

```env
ETG_ENABLE_TEST_FALLBACK=true
```

Это означает что при ошибках API или пустых результатах, система автоматически показывает демо-отели (включая `test_hotel`).

**Логика работы:**

```typescript
// Псевдокод логики:
if (FORCE_TEST_HOTELS) {
  return getDemoHotels(); // ← Тестовые отели
}

try {
  const results = await searchSerpRegion();
  if (results.length === 0) {
    return await searchSerpGeo(); // Fallback
  }
  return results;
} catch (error) {
  // В dev-режиме: показываем тестовые отели
  if (ETG_ENABLE_TEST_FALLBACK && NODE_ENV !== 'production') {
    return getDemoHotels(); // ← Тестовые отели при ошибке
  }
  return [];
}
```

**Почему вы видите test_hotel:**

1. **Логика ссылок:** Все demo-отели (moscow_ritz, spb_astoria и т.д.) мапятся на `test_hotel` при генерации реферальных ссылок, так как они не существуют в Ostrovok:

```typescript
// server/lib/ostrovok-links.cjs
if (hotelIdStr === 'test_hotel' || hotelIdStr === 'test_hotel_do_not_book') {
  return buildHotelPageLink(hotelIdStr, {...});
}
// Для всех остальных demo отелей
console.warn(`Demo hotel ID=${hotelIdStr}, using test_hotel fallback`);
return buildHotelPageLink('test_hotel', {...});
```

2. **API методы не триггерятся** — потому что в dev-режиме при ошибке аутентификации или пустых результатах срабатывает fallback раньше, чем реальный запрос к API.

**Решение:**

При переходе на production:
1. Установим `ETG_ENABLE_TEST_FALLBACK=false`
2. Все запросы будут идти напрямую к ETG API
3. Тестовые отели останутся только для тестирования с `ids: ['test_hotel']`

## 11. Реферальные ссылки

### Вопрос Островок:
> я заметила, что любой поисковой запрос в чате формирует одинаковую реферальную ссылку с некорректными датами и гостями.

### Ответ:

**Проблема понятна.** Ссылка формируется некорректно из-за fallback на test_hotel.

**Пример проблемной ссылки:**
```
https://ostrovok.ru/hotel/russia/belogorsk/mid8526976/test_hotel/...
```

**Причина:** 
1. В dev-режиме при ошибке API используется test_hotel
2. Для demo-отелей (moscow_ritz и др.) генерируется ссылка на test_hotel как fallback

**Исправление:**

После перехода на боевой API ссылки будут формироваться корректно:
- Для каждого отеля — своя реальная ссылка
- Даты и гости берутся из параметров поиска
- Формат: `https://www.ostrovok.ru/rooms/{hotel_slug}/?dates=DD.MM.YYYY-DD.MM.YYYY&guests=2`
