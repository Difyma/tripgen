## Проблемы ❌

### 1. Реальные hotel_id из API недоступны на сайте

При переходе по ссылкам с реальными `hotel_id` (полученными из API), открывается страница 404.

**Пример:**
- Запрос к API возвращает отель: `hid: 7497440` (Москва)
- Формируем ссылку: `https://ostrovok.ru/rooms/7497440/?partner_id=270392.affiliate.a0bd&check_in=2026-03-01&check_out=2026-03-03&guests=2`
- Результат: **404 Not Found**

**Вопрос:** Почему ID из B2B API не доступны на публичном сайте ostrovok.ru? Нужно ли использовать другой формат ссылок для реальных отелей?

### 2. Тестовые отели hid=1,2 недоступны через API

Для проверки корректности переходов нам нужны тестовые отели. Согласно документации, используем:
- `hid: 1` — test_hotel
- `hid: 2` — test_hotel_do_not_book

**Запрос:**
```json
POST /api/b2b/v3/search/serp/hotels/
{
  "hids": [1, 2],
  "checkin": "2026-03-01",
  "checkout": "2026-03-03",
  "guests": [{"adults": 2}],
  "language": "ru",
  "currency": "RUB"
}
```

**Ответ:**
```json
{
  "data": { "hotels": [] },
  "status": "ok",
  "error": null
}
```

**Вопрос:** Как получить тестовые отели для проверки интеграции? Возможно, нужны специальные параметры или тестовые даты?

### 3. SERP vs Hotelpage — что использовать?

Для поисковых ссылок (когда нет прямого `hotel_id`) используем формат:
```
https://ostrovok.ru/hotel/{city_slug}/?text={hotel_name}&partner_id=270392.affiliate.a0bd&...
```

**Вопрос:** Правильный ли это формат для партнерских переходов? Будет ли корректно засчитан клик и бронирование?
